## 1. 产品概述

### 1.1 产品定位

**智看视频** 是一个面向在线学习者的“视频理解与主动学习工作台”。

它的当前核心任务不是替代播放器，而是帮助用户在看长视频前后更快完成以下动作：

- 快速理解内容结构
- 快速定位关键片段
- 围绕结果开始记录笔记
- 为后续复习和知识沉淀建立入口

### 1.2 核心价值主张

- **节省时间**：用户不必完整重看长视频，也能快速把握重点
- **结构理解**：系统自动生成摘要、章节、转写，降低内容理解成本
- **开始学习**：笔记与结果页联动，让“理解”自然过渡到“记录”
- **持续沉淀**：后续逐步从“结果消费”演进到“主动复习与知识沉淀”

### 1.3 目标用户

| 用户类型 | 当前优先级 | 描述 | 典型场景 |
|---------|------------|------|---------|
| 在线学习者 | P0 | 观看教程、课程、技术分享类长视频，希望提高学习效率的用户 | 课程预习、课后回顾、知识梳理、快速定位重点 |
| 深度技术 / 学术内容学习者 | P1 | 观看高信息密度视频，希望把视频内容沉淀为结构化知识的用户 | 技术分享、论文解读、专题课程 |
| 企业 L&D / 内训场景 | P2 | 需要将内部培训视频资产化、可检索化的团队 | 培训复盘、知识复用、内部学习材料整理 |

#### 1.3.1 当前聚焦用户

当前版本继续聚焦第一类用户：**在线学习者**。

现阶段验证的最小价值是：

**用户上传一个学习类视频后，系统在可接受时间内生成可读摘要和可跳转章节，并允许用户直接在结果上下文中记笔记。**

### 1.4 差异化方向

与纯“视频总结工具”相比，智看视频后续要强化的不是摘要本身，而是“从理解到学习动作”的闭环。

当前已建立的差异化基础：

- 摘要、章节、转写、笔记围绕同一视频详情页联动
- 处理过程可见，状态更清晰
- 结果消费路径已经形成闭环，而不是停在模型输出文本

下一阶段要加强的差异化方向：

- 从“看结果”升级到“开始复习”
- 从“单次消费”升级到“长期沉淀”
- 从“内容摘要”升级到“学习工作台”

### 1.5 当前阶段判断

当前项目已经完成 MVP 定义范围内的前后端主闭环：

- 用户注册 / 登录
- 本地上传学习类视频
- 异步处理视频，生成摘要与章节
- 通过统一详情页查看处理状态与结果
- 在结果页内创建和删除基础笔记
- 在 Dashboard 回访历史视频

因此，本 PRD 当前不再以“补齐 MVP 是否可用”为核心，而以以下两类工作为主：

1. 优化现有产品体验和 AI 结果质量
2. 规划从“结果消费”向“主动学习”演进的下一阶段能力

## 2. 功能架构

### 2.1 当前产品结构

```text
智看视频
│
├─ 用户模块
│  ├─ 注册 / 登录
│  └─ 当前用户与数据归属
│
├─ 视频处理模块
│  ├─ 本地视频上传
│  ├─ 音频提取
│  ├─ Whisper 转写
│  ├─ AI 摘要生成
│  └─ AI 章节生成
│
├─ 结果消费模块
│  ├─ 统一视频详情页
│  ├─ 处理状态与阶段反馈
│  ├─ 摘要查看
│  ├─ 章节导航
│  ├─ 转写 / 字幕查看
│  └─ 失败重试
│
├─ 笔记模块
│  ├─ 按视频创建笔记
│  ├─ 删除笔记

   ├─ 历史视频列表
   ├─ 状态筛选
   └─ 回访入口
```

### 2.2 中期能力结构

结合 `Zhikan Prd V1.pdf`，中期产品演进方向新增以下模块，但**不等于当前全部开做**：

```text
主动学习层（规划）
├─ AI 抽认卡 / 重点回顾
├─ AI 问答
├─ 课件 OCR / 屏幕文字提取
├─ 笔记同步与导出
└─ 轻量知识沉淀

企业化方向（规划）
├─ 团队视频资产化
├─ 可检索知识沉淀
├─ 私有化 / 权限控制
└─ 培训评估与复盘
```

### 2.3 功能优先级

| 优先级 | 功能模块 | 说明 |
|-------|---------|------|
| P0 | 本地上传 + 摘要 + 章节 + 统一详情页 | 当前核心闭环 |
| P0 | 结果页内笔记 + Dashboard 回访 | 当前核心闭环的一部分 |
| P1 | AI 结果质量优化 / 状态流稳定性 / 页面体验优化 | 当前迭代重点 |
| P1 | 主动学习入口：抽认卡 / AI 问答 / 导出同步 | 下一阶段优先规划能力 |
| P2 | OCR 课件提取 / 视频到知识卡片沉淀 | 需结合真实学习场景验证 |
| P3 | URL 导入 / 企业版 / 多人协作 | 中长期扩展方向 |

#### 2.3.1 当前版本范围

当前实际已落地范围：

- 用户注册 / 登录
- 本地上传学习类视频
- 视频处理：音频提取、ASR、摘要、章节
- 统一详情页查看状态、摘要、章节、转写与笔记
- Dashboard 查看历史处理记录
- 基础失败重试

#### 2.3.2 当前明确不进入本轮开发重点

- 完整知识库闭环
- 多人协作
- 社区分享
- 重型企业权限系统
- 大范围 URL 导入支持

这些方向保留为路线图，但不作为当前版本承诺能力。

## 3. 用户旅程

### 3.1 当前首次用户旅程

```text
1. 访问首页
   ├─ 理解产品定位
   └─ 看到可直接使用的上传入口

2. 注册 / 登录
   └─ 建立当前用户会话

3. 上传本地视频
   └─ 上传成功后直接进入统一详情页 /video/:id

4. 等待处理
   ├─ 查看处理阶段与阶段说明
   ├─ 通过 SSE 获取状态变化
   └─ 异常时可重试

5. 查看结果
   ├─ 阅读摘要
   ├─ 浏览章节
   ├─ 查看转写 / 字幕
   └─ 创建笔记

6. 回访
   └─ 在 Dashboard 中查看历史视频并继续使用
```

### 3.2 当前回访用户旅程

```text
1. 登录
   └─ 进入 Dashboard

2. 选择历史视频
   └─ 进入统一视频详情页

3. 继续使用
   ├─ 重新查看摘要 / 章节 / 转写
   ├─ 继续记笔记
   └─ 对失败任务执行重试
```

### 3.3 下一阶段目标旅程

下一阶段不改变主链路，而是在详情页结果态上补充更强的学习动作：

```text
查看结果
  ├─ 生成重点回顾 / 抽认卡
  ├─ 围绕视频内容发起 AI 问答
  ├─ 导出到外部笔记工具
  └─ 进入后续复习
```

## 4. 详细功能说明

### 4.1 首页

#### 4.1.1 当前定位

首页当前不是单纯宣传页，而是“产品首页 + 上传入口”的组合页。

#### 4.1.2 当前职责

| 元素 | 当前职责 |
|------|---------|
| 顶部导航 | 承接品牌、登录注册与后续产品信息架构 |
| Hero 区 | 解释产品价值并突出上传入口 |
| 上传工作台 | 直接承接本地 MP4 上传能力 |
| 能力速览 | 说明上传后能得到什么结果 |
| 占位导航页 | 为未落地页面预留统一入口，不误导为已完成能力 |

#### 4.1.3 当前约束

- 首页必须保留真实上传能力，不做纯展示稿
- 首页允许承接产品化表达，但不能展示当前未具备的核心能力为“已上线”

---

### 4.2 用户认证

#### 4.2.1 当前已实现

| 功能 | 状态 |
|------|------|
| 注册 | 已实现 |
| 登录 | 已实现 |
| 登出 | 已实现 |
| 当前用户查询 | 已实现 |
| 登录态维持 | 已实现，基于 `HttpSession` |

#### 4.2.2 后续可扩展

- 忘记密码
- 第三方登录
- 邮箱验证

---

### 4.3 Dashboard

#### 4.3.1 当前定位

Dashboard 当前主要承担“历史视频回访入口”，而不是完整工作台或后台管理页。

#### 4.3.2 当前已实现

- 展示当前用户历史视频列表
- 支持按状态筛选
- 支持从列表直接进入统一详情页

#### 4.3.3 当前核心信息

每条视频记录需至少展示：

- 视频标题
- 处理状态
- 时长
- 创建时间
- 快捷入口

---

### 4.4 视频处理

#### 4.4.1 当前处理链路

```text
上传视频
  -> 提取音频（FFmpeg）
  -> Whisper 转写
  -> AI 摘要
  -> AI 章节
  -> 写入 summary / chapters / transcript
  -> SUCCESS
```

#### 4.4.2 当前输入边界

| 功能 | 说明 |
|------|------|
| 上传方式 | 本地文件上传 |
| 当前支持格式 | `mp4` |
| 单文件大小 | 1GB 以内 |
| 视频时长 | 2 小时以内 |

#### 4.4.3 URL 导入

| 项目 | 当前判断 |
|------|---------|
| 当前状态 | 不进入当前阶段 |
| 是否彻底放弃 | 否 |
| 当前原因 | 涉及版权、平台兼容、下载失败处理和成本问题 |

#### 4.4.4 当前状态设计

当前产品层面需要让用户感知两层状态：

1. **结果状态**：`WAITING / PROCESSING / SUCCESS / FAILED`
2. **处理阶段**：如提音频、转写、生成摘要、生成章节等

前端当前采用：

- 首次状态快照
- SSE 状态推送
- 断线后的兜底刷新

#### 4.4.5 当前成功定义

- A 级成功：摘要和章节都可展示
- B 级成功：摘要可用，章节可降级展示
- 失败：转写失败，或结果完全不可读

当前产品优先级仍然是：

1. 可读摘要
2. 可用章节
3. 笔记入口

---

### 4.5 快速视频摘要

#### 4.5.1 当前目标

帮助用户先理解视频讲了什么、重点是什么，而不是直接把整段转写甩给用户。

#### 4.5.2 当前要求

- 摘要必须可读
- 能覆盖视频主旨和关键点
- 对短视频和长视频都要保持基本可消费性

#### 4.5.3 后续增强方向

- 长视频分段摘要与汇总
- 更稳定的结构化摘要模板
- 面向复习的重点提炼

---

### 4.6 章节划分与导航

#### 4.6.1 当前目标

章节的价值不是生成漂亮标题，而是帮助用户快速跳到想看的位置。

#### 4.6.2 当前要求

- 章节必须具备基本导航价值
- 时间戳允许小误差，但不能完全失去可用性
- 短视频场景允许单章节兜底

#### 4.6.3 后续增强方向

- 更稳的长视频章节切分
- 与转写分段、字幕区域更强联动
- 后续再评估是否开放人工微调

---

### 4.7 统一视频详情页

#### 4.7.1 当前定位

统一视频详情页 `/video/:id` 已取代早期“状态页 / 结果页”双页模式，成为当前最核心的产品页面。

#### 4.7.2 当前职责

| 区域 | 当前职责 |
|------|---------|
| 状态区 | 展示处理阶段、错误信息、重试入口 |
| 结果区 | 展示摘要、章节、转写 / 字幕 |
| 笔记区 | 结果态下进行笔记增删 |
| 视频区 | 承接播放器与时间信息 |

#### 4.7.3 当前原则

- 所有状态尽量在同一路由下切换
- 不再把“处理中”和“成功”强拆成两个完全不同页面
- 结果内容和笔记能力保持同上下文联动

---

### 4.8 笔记系统

#### 4.8.1 当前定位

笔记系统当前是“结果页内的学习动作”，不是独立笔记产品。

#### 4.8.2 当前已实现

- 按视频查询笔记
- 创建笔记
- 删除笔记
- 用户与视频归属隔离

#### 4.8.3 当前不追求

- 大而全的笔记中心
- 标签体系
- 独立知识库管理台

#### 4.8.4 后续方向

- 从摘要 / 章节内容生成重点回顾
- 面向复习的卡片化沉淀
- 导出到外部笔记工具

---

### 4.9 知识库

知识库能力保留为产品方向，但**不属于当前实现范围**。

当前判断：

- 现阶段不单独扩展“知识库中心”
- 更适合先从结果页上的轻量导出、卡片化沉淀和复习动作做起
- 完整知识库闭环应在主动学习链路被验证后再推进

---

## 5. 非功能性需求

### 5.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | 常规页面尽量控制在 3 秒内 |
| 视频处理时间 | 10 分钟视频尽量 3 分钟内；30 分钟视频尽量 10 分钟内；长视频必须展示明确状态 |
| 状态反馈 | 处理中用户需要能看到阶段变化，而不是长时间无反馈 |

### 5.2 兼容性要求

| 平台 | 要求 |
|------|------|
| 浏览器 | Chrome 优先，兼容主流现代浏览器 |
| 操作系统 | Windows、macOS、Linux |
| 移动端 | 当前以桌面体验优先，移动端逐步适配 |

### 5.3 安全性要求

| 项目 | 要求 |
|------|------|
| 用户密码 | 加密存储 |
| 数据隔离 | 用户只能访问自己的视频和笔记 |
| 文件留存 | 原视频默认保留 7 天，音频默认保留 24 小时 |
| 敏感配置 | 通过环境变量或环境隔离方式覆盖 |

### 5.4 可用性要求

| 项目 | 要求 |
|------|------|
| 错误处理 | 对失败场景给出可理解错误信息 |
| 重试能力 | 处理失败场景支持重试 |
| 一致性 | 首页、Dashboard、详情页需逐步统一布局和视觉基线 |

## 6. 技术架构

### 6.1 当前技术栈

| 层级 | 技术选型 |
|------|---------|
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | Java 21 + Spring Boot |
| 数据访问 | MyBatis-Plus + MySQL |
| AI 集成 | Spring AI + 多模型路由 |
| 视频处理 | FFmpeg |
| 语音识别 | Whisper（当前以本地模型策略为主） |
| 状态推送 | SSE |
| 文件存储 | 本地文件系统 |

### 6.2 当前系统结构

```text
前端页面
  -> REST API / SSE
  -> 用户服务 / 视频服务 / 笔记服务
  -> 音频提取 / Whisper 转写 / AI 摘要 / AI 章节
  -> MySQL + 本地文件系统
```

### 6.3 当前核心数据模型

#### 6.3.1 用户（User）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 用户 ID |
| userAccount | String | 账号标识 |
| userPassword | String | 加密密码 |
| userName | String | 用户昵称 |
| avatarUrl | String | 头像 |

#### 6.3.2 视频（Video）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 视频 ID |
| userId | Long | 用户 ID |
| title | String | 视频标题 |
| url | String | 视频文件路径 |
| duration | Long | 视频时长（秒） |
| fileSize | Long | 文件大小 |
| status | String | 结果状态 |
| stage | String | 当前处理阶段 |
| stageMessage | String | 阶段说明 |
| transcript | Text | 转写文本 |
| summary | Text | 摘要内容 |
| chapters | Json | 章节 JSON |
| errorMessage | Text | 错误信息 |

#### 6.3.3 笔记（Note）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 笔记 ID |
| userId | Long | 用户 ID |

## 9. 风险与挑战

### 9.1 当前技术风险

| 风险 | 影响 | 应对方向 |
|------|------|---------|
| ASR 识别质量不稳定 | 影响摘要和章节质量 | 持续优化 Prompt、策略与模型选择 |
| 长视频链路时延高 | 影响等待体验 | 分段策略、阶段反馈、降级策略 |
| 外部依赖较多 | 影响部署与稳定性 | 明确依赖、加强运行文档与错误处理 |

### 9.2 当前产品风险

| 风险 | 影响 | 应对方向 |
|------|------|---------|
| 范围膨胀 | 稀释当前主闭环质量 | 将愿景能力拆到路线图和专项文档 |
| 结果有用但学习动作不足 | 用户停留在“看一眼总结” | 优先规划主动学习入口 |
| 过早做重型知识库或企业版 | 分散研发资源 | 先验证轻量复习和导出能力 |
