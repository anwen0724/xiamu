# 项目文档维护规范

## 1. 文档目标

本文档用于统一项目开发过程中的文档维护方式，避免文档碎片化、重复记录或长期失效。后续新增功能和模块时，统一按本规范更新。

## 2. 文档分层

项目文档分为三层：

### 2.1 总控文档

用于维护项目级信息，不记录过多实现细节。

- `MVP开发说明.md`：维护 MVP 目标、范围、边界、成功标准、总体进度
- `MVP开发任务拆解.md`：维护开发顺序、阶段任务、优先级、当前重点

### 2.2 模块文档

用于维护某一个模块的详细设计与实现过程。  
按模块建文档，不按单个小功能建文档。

当前已有：

- `视频处理模块开发文档.md`

后续如有需要，可新增：

- `用户模块开发文档.md`
- `笔记模块开发文档.md`
- `Dashboard模块开发文档.md`

### 2.3 迭代记录

每个模块文档末尾维护“迭代记录”或“开发进度”章节，用于记录本次具体实现了什么。  
不建议每完成一个小功能就单独新建一篇文档。

## 3. 什么时候更新文档

以下情况必须更新文档：

- 完成一个可独立验收的功能
- 模块范围发生变化
- 数据结构发生变化
- 接口发生变化
- 状态流转或核心流程发生变化
- 明确新增风险、限制或遗留问题

如果只是小规模重构、命名调整、注释补充，通常不单独更新项目文档。

## 4. 各类文档的维护规则

### 4.1 总控文档维护规则

- 只更新范围、阶段、进度、优先级
- 不写过细的实现步骤
- 做完一个阶段后再更新，不要求每次小改都更新

### 4.2 模块文档维护规则

每份模块文档建议固定包含以下内容：

- 模块目标
- 功能范围
- 数据结构
- 接口设计
- 核心流程
- 状态设计
- 当前实现进度
- 已知问题
- 后续计划
- 迭代记录

模块文档应持续追加，不要反复拆成很多零散子文档。

### 4.3 迭代记录维护规则

每次完成一个功能后，在对应模块文档末尾追加一条记录，建议包含：

- 日期
- 本次实现内容
- 涉及文件
- 数据库变更
- 接口变更
- 遗留问题
- 下一步

## 5. 推荐维护方式

后续开发时，统一按以下顺序维护：

1. 先实现代码
2. 功能完成后更新对应模块文档
3. 如影响 MVP 范围或整体进度，再更新总控文档

也就是说，文档维护以“模块文档”为主，以“总控文档”为辅。

## 6. 不推荐的做法

- 每实现一个小功能就新建一篇文档
- 把所有内容都堆到一个总文档里
- 只改代码，不同步更新接口、流程或进度说明
- 在多个文档里重复写同一份实现细节

## 7. 当前执行约定

从现在开始，文档维护按以下方式执行：

- 项目级信息更新到 `MVP开发说明.md` 和 `MVP开发任务拆解.md`
- 视频处理相关实现继续维护在 `视频处理模块开发文档.md`
- 后续新模块启动时，再新增对应模块文档
- 每完成一个可独立说明的功能，在对应模块文档中补充一条迭代记录

## 8. 一句话原则

项目文档看全局，模块文档记实现，迭代记录追踪变化；按模块维护，不按零散功能维护。
