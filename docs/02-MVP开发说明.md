# 智看视频 MVP 开发说明

## 1. 文档目标

本文档用于统一 MVP 阶段的目标用户、功能边界、验收标准、开发顺序与当前进度，避免范围持续膨胀。

## 2. MVP 一句话定义

面向在线学习者，提供一个“上传学习类视频后，自动生成可读摘要和可点击章节，并支持开始记笔记”的最小可用闭环。

## 3. MVP 范围

### 3.1 本期必须做

- 用户注册 / 登录
- 本地上传学习类视频
- 视频基础信息存储
- 音频提取
- ASR 转写
- AI 生成摘要
- AI 生成章节与时间戳
- 结果页展示摘要与章节导航
- 创建基础笔记
- Dashboard 展示最近处理记录

### 3.2 本期明确不做

- URL 导入
- 多平台内容抓取
- 多人协作
- 社区分享
- 完整知识库
- AI 测试题
- 学习计划

### 3.3 可降级但不能缺失的能力

- 摘要优先于章节
- 章节允许不完美，但必须具备基本可导航价值
- 不接受“处理成功但没有任何可读结果”

## 4. 用户主流程

1. 用户注册或登录系统
2. 上传本地学习类视频
3. 系统保存视频并进入异步处理
4. 系统完成音频提取、转写、摘要和章节生成
5. 用户进入结果页查看摘要与章节
6. 用户基于结果开始创建笔记
7. 用户在 Dashboard 查看历史处理记录并回访内容

## 5. 功能清单与验收标准

### 5.1 用户认证

- 支持基础注册与登录
- 能识别用户身份，并将视频、笔记与用户关联
- 验收标准：用户能独立登录并查看自己的数据

### 5.2 视频上传

- 支持本地文件上传
- 限制格式、大小、时长
- 验收标准：上传成功后可落库并返回视频记录

### 5.3 视频处理链路

- 视频转音频
- 音频转文本
- 文本生成摘要
- 文本生成章节与时间戳
- 验收标准：至少产出摘要或可用章节，其一缺失时需明确标记为降级结果

### 5.4 结果页

- 展示视频基础信息
- 展示摘要
- 展示章节列表与时间跳转信息
- 验收标准：用户能基于结果快速理解内容重点

### 5.5 基础笔记

- 支持创建、编辑、删除笔记
- 支持与视频关联
- 验收标准：用户能围绕某个视频完成最基本的学习记录

### 5.6 Dashboard

- 展示最近处理的视频列表
- 展示处理状态与快捷入口
- 验收标准：用户能快速回到历史内容继续使用

## 6. 处理链路与状态设计

### 6.1 推荐处理链路

`上传视频 -> 保存文件 -> 提取视频信息 -> 提取音频 -> ASR 转写 -> AI 摘要 -> AI 章节 -> 结果展示`

### 6.2 状态定义

- `WAITING`：等待下一步处理
- `PROCESSING`：当前步骤处理中
- `SUCCESS`：已产出可展示的最终结果
- `FAILED`：处理失败，需记录错误信息

### 6.3 成功分级

- A 级成功：摘要和章节都生成，章节可跳转
- B 级成功：摘要成功，章节质量一般但仍可展示
- C 级结果：转写成功，但摘要或章节未生成，只能视为中间态或待重试，不应直接算最终成功
- 失败：转写失败，或最终结果不可读

## 7. 非功能边界

- 仅支持本地上传，不开放 URL 导入
- 第一版建议仅稳定支持 `mp4`
- 单文件大小上限：`1GB`
- 单视频时长上限：`2 小时`
- 原视频默认保留 `7 天`
- 提取后的音频默认保留 `24 小时`
- 转写文本、摘要、章节结果长期保留
- 10 分钟以内视频，尽量 3 分钟内完成处理
- 30 分钟以内视频，尽量 10 分钟内完成处理
- 超长视频必须向用户展示明确处理状态和阶段信息

## 8. 开发优先级与迭代顺序

### Phase 1：上传与基础存储

- 视频上传
- 文件校验
- 本地存储
- 视频信息落库

### Phase 2：音频提取与转写

- FFmpeg 提取音频
- Whisper 转写
- 状态与错误信息落库

### Phase 3：AI 内容生成

- 生成摘要
- 生成章节与时间戳
- 定义最终成功与降级成功

### Phase 4：结果页与基础笔记

- 结果查询接口
- 摘要与章节展示
- 基础笔记增删改查

### Phase 5：Dashboard 与 MVP 补齐

- 历史记录查询
- 用户体系补齐
- 文件生命周期管理
- 重试与基础测试

## 9. MVP 成功指标

- 摘要页打开率
- 章节点击率
- 笔记创建率
- 二次上传率
- 视频处理成功率
- 用户 7 日留存率

## 10. 风险与当前工程注意点

- Whisper 对语速快、口音重或音质差的视频识别准确率有限
- 长视频会拉长处理链路，容易造成等待体验变差
- 本地文件与音频会持续占用磁盘，需要生命周期管理
- Python、Whisper、FFmpeg 都是外部依赖，部署稳定性需要验证
- 当前处理链路偏异步串行，后续需要考虑失败重试与更清晰的阶段状态
