# 视频处理模块开发文档

## 模块概述

视频处理模块是智看视频的核心功能，负责视频的上传、处理、分析和内容提取。

## 处理流程

```
视频上传/导入
    │
    ▼
音频提取 (FFmpeg)
    │
    ▼
ASR 转文字 (Whisper)
    │
    ▼
AI 内容分析
    ├─ 生成摘要
    ├─ 章节划分
    └─ 内容分类
    │
    ▼
处理完成
```

## 第一步：视频上传 + 基础信息存储

### 目标

实现视频文件上传接口，将视频保存到本地，提取基本信息并存入数据库。

### 功能需求

| 功能 | 说明 |
|------|------|
| 文件上传 | 接收 multipart/form-data 格式的视频文件 |
| 文件校验 | 校验文件格式、大小 |
| 本地存储 | 按日期分目录存储视频文件 |
| 信息提取 | 使用 FFmpeg 提取视频时长、格式等信息 |
| 数据持久化 | 保存视频记录到数据库 |

### 技术选型

| 组件 | 技术 |
|------|------|
| 视频上传 | Spring MultipartFile |
| FFmpeg 集成 | ffmpeg-cli-wrapper (Java 命令行工具库) |
| 文件存储 | 本地文件系统 |
| 数据库 | MySQL (MyBatis-Plus) |

#### SQL 建表语句

```sql
CREATE TABLE `video` (
    `id` BIGINT NOT NULL COMMENT '视频ID',
    `userId` BIGINT DEFAULT NULL COMMENT '用户ID',
    `title` VARCHAR(255) NOT NULL COMMENT '视频标题',
    `url` VARCHAR(512) NOT NULL COMMENT '视频文件路径',
    `duration` BIGINT DEFAULT 0 COMMENT '视频时长（秒）',
    `fileSize` BIGINT NOT NULL COMMENT '文件大小（字节）',
    `status` VARCHAR(20) NOT NULL DEFAULT 'WAITING' COMMENT '处理状态: WAITING/PROCESSING/SUCCESS/FAILED',
    `transcript` TEXT COMMENT '转写文本',
    `summary` TEXT COMMENT '摘要内容',
    `chapters` JSON COMMENT '章节数据',
    `type` VARCHAR(20) NOT NULL COMMENT '视频类型: UPLOAD/URL',
    `format` VARCHAR(20) NOT NULL COMMENT '视频格式: mp4/avi/mkv/webm',
    `errorMessage` TEXT COMMENT '错误信息',
    `createTime` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updateTime` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `isDelete` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0未删除/1已删除',
    PRIMARY KEY (`id`),
    KEY `idx_userId` (`userId`),
    KEY `idx_createTime` (`createTime`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='视频表';
```

#### 步骤 6：创建文件存储工具类

**为什么要这样做**：
- 将文件存储相关的操作封装成工具类，实现职责分离
- 复用性高，其他需要文件操作的地方也可以使用
- 便于单元测试和维护

**达到什么目的**：
- 提供保存视频文件的方法，包含完整的校验和保存逻辑
- 校验文件：非空校验、大小校验、格式校验
- 生成唯一文件名（使用时间戳避免重复）
- 按日期分目录存储，便于管理和查找
- 解析文件大小配置（支持 GB/MB/KB 单位）
- **使用 java.nio.file.Path 实现跨平台路径处理**

文件位置：`src/main/java/com/anwen/xiamubackend/utils/FileStorageUtil.java`

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class FileStorageUtil {

    private final StorageConfig storageConfig;

    /**
     * 保存视频文件
     * @param file 上传的文件
     * @return 保存后的文件路径
     */
    public String saveVideo(MultipartFile file) {
        // 校验文件
        validateFile(file);

        // 生成文件名
        String fileName = generateFileName(file.getOriginalFilename());

        // 生成存储路径（跨平台）
        Path relativePath = generateRelativePath();
        Path fullPath = Paths.get(storageConfig.getVideoPath(), relativePath.toString(), fileName);

        // 确保目录存在
        File directory = fullPath.getParent().toFile();
        if (!directory.exists()) {
            directory.mkdirs();
        }

        // 保存文件
        try {
            file.transferTo(fullPath.toFile());
            log.info("视频文件保存成功: {}", fullPath);
            return fullPath.toString();
        } catch (IOException e) {
            log.error("视频文件保存失败", e);
            throw new BusinessException(ErrorCode.SYSTEM_ERROR, "文件保存失败");
        }
    }

    /**
     * 校验文件
     */
    private void validateFile(MultipartFile file) {
        if (file == null || file.isEmpty()) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "文件不能为空");
        }

        // 校验文件大小
        long size = file.getSize();
        long maxSize = parseSize(storageConfig.getMaxFileSize());
        if (size > maxSize) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "文件大小超过限制");
        }

        // 校验文件格式
        String originalFilename = file.getOriginalFilename();
        if (originalFilename == null) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "文件名不能为空");
        }

        String extension = getFileExtension(originalFilename);
        List<String> allowedFormats = storageConfig.getAllowedFormats();
        if (!allowedFormats.contains(extension.toLowerCase())) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "文件格式不支持");
        }
    }

    /**
     * 生成文件名
     */
    private String generateFileName(String originalFilename) {
        String extension = getFileExtension(originalFilename);
        return "video_" + System.currentTimeMillis() + "." + extension;
    }

    /**
     * 生成相对路径（按日期）
     * @return 日期路径对象
     */
    private Path generateRelativePath() {
        LocalDate now = LocalDate.now();
        return Paths.get(
            String.valueOf(now.getYear()),
            String.format("%02d", now.getMonthValue()),
            String.format("%02d", now.getDayOfMonth())
        );
    }

    /**
     * 获取文件扩展名
     */
    private String getFileExtension(String filename) {
        int lastDot = filename.lastIndexOf('.');
        if (lastDot > 0) {
            return filename.substring(lastDot + 1);
        }
        return "";
    }

    /**
     * 解析文件大小
     */
    private long parseSize(String size) {
        if (size == null) {
            return 2L * 1024 * 1024 * 1024; // 默认 2GB
        }
        size = size.toUpperCase().trim();
        if (size.endsWith("GB")) {
            return Long.parseLong(size.substring(0, size.length() - 2)) * 1024 * 1024 * 1024;
        } else if (size.endsWith("MB")) {
            return Long.parseLong(size.substring(0, size.length() - 2)) * 1024 * 1024;
        } else if (size.endsWith("KB")) {
            return Long.parseLong(size.substring(0, size.length() - 2)) * 1024;
        } else {
            return Long.parseLong(size);
        }
    }
}
```

#### 步骤 7：创建 FFmpeg 工具类

**为什么要这样做**：
- 封装 FFmpeg 相关的操作，隐藏底层实现细节
- 方便后续切换 FFmpeg 库，只需修改这个类
- 统一异常处理和日志记录

**达到什么目的**：
- 提供获取视频信息的方法，调用 FFprobe 分析视频文件
- 提取关键信息：时长、格式、分辨率、帧率
- 使用内部类 VideoInfo 封装返回的视频信息
- 异常处理：获取失败时抛出业务异常

文件位置：`src/main/java/com/anwen/xiamubackend/utils/FFmpegUtil.java`

```java
@Slf4j
@Component
public class FFmpegUtil {

  /**
   * 获取视频信息
   * @param videoPath 视频文件路径
   * @return 视频信息
   */
  public VideoInfo getVideoInfo(String videoPath) {
    try {
      FFprobe probe = FFprobe.atPath();
      FFprobeResult result = probe.setInput(videoPath).execute();

      List<Stream> streams = result.getStreams();
      if (streams.isEmpty()) {
        throw new BusinessException(ErrorCode.SYSTEM_ERROR, "无法获取视频信息：视频流为空");
      }

      // 查找视频流
      Stream videoStream = streams.stream()
              .filter(s -> s.getCodecType() == StreamType.VIDEO)
              .findFirst()
              .orElse(streams.get(0));

      VideoInfo info = new VideoInfo();

      // 获取时长（秒）
      Float duration = result.getFormat().getDuration();
      if (duration != null) {
        info.setDuration(duration.longValue());
      }

      // 获取格式（编码格式）
      String codec = videoStream.getCodecName();
      if (codec != null) {
        info.setFormat(codec);
      }

      // 获取分辨率
      info.setWidth(videoStream.getWidth());
      info.setHeight(videoStream.getHeight());

      // 获取帧率
      Rational frameRate = videoStream.getRFrameRate();
      if (frameRate != null) {
        double fps = (double) frameRate.getNumerator() / frameRate.getDenominator();
        info.setFrameRate(String.format("%.2f", fps));
      }

      log.info("视频信息获取成功: duration={}s, format={}, {}x{}, fps={}",
              info.getDuration(), info.getFormat(), info.getWidth(), info.getHeight(), info.getFrameRate());

      return info;

    } catch (BusinessException e) {
      throw e;
    } catch (Exception e) {
      log.error("获取视频信息失败: {}", videoPath, e);
      throw new BusinessException(ErrorCode.SYSTEM_ERROR, "获取视频信息失败: " + e.getMessage());
    }
  }

    /**
     * 视频信息内部类
     */
    @Data
    public static class VideoInfo {
        private Long duration;      // 时长（秒）
        private String format;      // 格式
        private Integer width;      // 宽度
        private Integer height;     // 高度
        private String frameRate;   // 帧率
    }
}
```

文件位置：`src/main/java/com/anwen/xiamubackend/utils/AudioExtractUtil.java`

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class AudioExtractUtil {

    private final StorageConfig storageConfig;

    /**
     * 从视频提取音频
     * @param videoPath 视频文件路径
     * @return 音频文件路径
     */
    public String extractAudio(String videoPath) {
        // 生成音频文件路径
        String audioPath = generateAudioPath(videoPath);

        // 确保输出目录存在
        Path outputPath = Paths.get(audioPath);
        File outputDir = outputPath.getParent().toFile();
        if (!outputDir.exists()) {
            outputDir.mkdirs();
        }

        try {
            log.info("开始提取音频: {} -> {}", videoPath, audioPath);

            // 使用 FFmpeg 提取音频
            FFmpeg.atPath()
                    .addInput(UrlInput.fromPath(Paths.get(videoPath)))
                    .addOutput(UrlOutput.toPath(outputPath)
                            // 设置音频编解码器为 mp3
                            .setMainStreamType(StreamType.AUDIO)
                            // 设置音频编码器
                            .setAudioCodec("libmp3lame")
                            // 设置采样率：16000 Hz（Whisper 推荐）
                            .setAudioSampleRate(16000)
                            // 设置声道：1（单声道）
                            .setAudioChannels(1)
                            // 设置比特率：64 kbps
                            .setAudioBitRate(64000))
                    .setOverwriteOutput(true)
                    .execute();

            log.info("音频提取成功: {}", audioPath);
            return audioPath;

        } catch (Exception e) {
            log.error("音频提取失败: {}", videoPath, e);
            throw new BusinessException(ErrorCode.SYSTEM_ERROR, "音频提取失败: " + e.getMessage());
        }
    }

    /**
     * 生成音频文件路径
     * @param videoPath 视频文件路径
     * @return 音频文件路径
     */
    private String generateAudioPath(String videoPath) {
        // 获取视频文件的日期路径（如 2026/03/07）
        LocalDate now = LocalDate.now();
        String datePath = Paths.get(
                String.valueOf(now.getYear()),
                String.format("%02d", now.getMonthValue()),
                String.format("%02d", now.getDayOfMonth())
        ).toString();

        // 生成音频文件名（使用视频文件名的时间戳部分）
        Path videoFileName = Paths.get(videoPath).getFileName();
        String videoName = videoFileName.toString();
        String nameWithoutExt = videoName.substring(0, videoName.lastIndexOf('.'));
        String audioName = "audio_" + nameWithoutExt.replace("video_", "") + ".mp3";

        // 构建完整路径
        return Paths.get(storageConfig.getAudioPath(), datePath, audioName).toString();
    }
}
```

**注意**：
- 需要导入 `com.anwen.xiamubackend.exception.BusinessException` 和 `ErrorCode`
- 需要导入 `com.anwen.xiamubackend.config.StorageConfig`
- FFmpeg 参数说明：
  - `-vn`：禁用视频（由 `setMainStreamType(StreamType.AUDIO)` 替代）
  - `-acodec libmp3lame`：使用 MP3 编码器
  - `-ar 16000`：采样率 16000 Hz
  - `-ac 1`：单声道
  - `-ab 64k`：比特率 64 kbps

#### 步骤 4：创建异步音频提取服务

**为什么要这样做**：
- 音频提取是耗时操作，不应阻塞上传接口
- 使用 Spring @Async 实现异步处理
- 解耦业务逻辑，便于维护和测试

**达到什么目的**：
- 创建音频提取服务，提供异步提取方法
- 处理成功后更新 Video 实体的 audioPath 和状态
- 处理失败后更新 errorMessage 和状态为 FAILED
- 记录详细的处理日志

文件位置：`src/main/java/com/anwen/xiamubackend/service/AudioExtractService.java`

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class AudioExtractService {

    private final VideoMapper videoMapper;
    private final AudioExtractUtil audioExtractUtil;

    /**
     * 异步提取音频
     * @param videoId 视频ID
     */
    @Async
    public void extractAudioAsync(Long videoId) {
        log.info("开始异步提取音频: videoId={}", videoId);

        // 1. 查询视频信息
        Video video = videoMapper.selectById(videoId);
        if (video == null) {
            log.error("视频不存在: videoId={}", videoId);
            return;
        }

        // 2. 检查视频路径
        if (video.getUrl() == null || video.getUrl().isEmpty()) {
            log.error("视频路径为空: videoId={}", videoId);
            updateExtractFailed(video, "视频路径为空");
            return;
        }

        // 3. 更新状态为处理中
        updateStatus(video, VideoStatusEnum.PROCESSING.getCode());

        try {
            // 4. 提取音频
            String audioPath = audioExtractUtil.extractAudio(video.getUrl());

            // 5. 更新数据库
            video.setAudioPath(audioPath);
            video.setStatus(VideoStatusEnum.WAITING.getCode());  // 提取成功，等待下一步 ASR
            videoMapper.updateById(video);

            log.info("音频提取成功: videoId={}, audioPath={}", videoId, audioPath);

        } catch (Exception e) {
            log.error("音频提取失败: videoId={}", videoId, e);
            updateExtractFailed(video, "音频提取失败: " + e.getMessage());
        }
    }

    /**
     * 更新状态
     */
    private void updateStatus(Video video, String status) {
        video.setStatus(status);
        videoMapper.updateById(video);
    }

    /**
     * 更新提取失败
     */
    private void updateExtractFailed(Video video, String errorMessage) {
        video.setStatus(VideoStatusEnum.FAILED.getCode());
        video.setErrorMessage(errorMessage);
        videoMapper.updateById(video);
    }
}
```

   - 应该看到 "开始异步提取音频" 日志
   - 应该看到 "音频提取成功" 日志
5. 验证音频文件：
   - 使用播放器打开音频文件，确认可以正常播放
   - 检查音频格式、采样率等参数

### 注意事项

1. **异步执行**：音频提取是异步执行的，上传接口会立即返回，音频提取在后台进行
2. **状态查询**：前端可以通过查询接口轮询视频状态，了解音频提取进度
3. **错误重试**：当前版本不支持自动重试，提取失败需要用户重新上传
4. **文件清理**：音频提取后保留视频文件，用户可能需要回看
5. **大文件处理**：大视频文件的音频提取可能需要较长时间，需要合理设置超时时间

#### 步骤 1：创建 Python 脚本

**为什么要这样做**：

**达到什么目的**：
- 接收音频文件路径作为参数

文件位置：`scripts/whisper_openai.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Whisper ASR 脚本（openai-whisper 官方版本）
用于将音频文件转写为文本
"""

import sys
import os
import whisper
import json

def transcribe_audio(audio_path):
    """
    转写音频文件
    :param audio_path: 音频文件路径
    :return: JSON 格式的转写结果
    """
    try:
        # 规范化路径（处理 Windows 路径问题）
        audio_path = os.path.normpath(audio_path)

        # 检查文件是否存在
        if not os.path.exists(audio_path):
            raise FileNotFoundError(f"音频文件不存在: {audio_path}")

        # 加载模型（small 模型）
        model = whisper.load_model("small")

        # 执行转写
        result = model.transcribe(
            audio_path,
            language=None,
            task="transcribe",
            verbose=False,
            fp16=False
        )

        # 构建返回结果
        output = {
            "text": result.get("text", ""),
            "segments": [],
            "language": result.get("language", ""),
            "language_probability": result.get("language_probability", 0.0)
        }

        for i, segment in enumerate(result.get("segments", [])):
            segment_data = {
                "id": i,
                "start": segment.get("start", 0),
                "end": segment.get("end", 0),
                "text": segment.get("text", "")
            }
            output["segments"].append(segment_data)

        # 输出 JSON（添加 indent=2，去掉 ensure_ascii=False）
        print(json.dumps(output, indent=2))

        return output

    except FileNotFoundError as e:
        error = {"error": f"音频文件不存在: {str(e)}"}
        print(json.dumps(error, indent=2))
        sys.exit(1)

    except Exception as e:
        error = {"error": f"转写失败: {str(e)}"}
        print(json.dumps(error, indent=2))
        sys.exit(1)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print(json.dumps({"error": "请提供音频文件路径"}, indent=2))
        sys.exit(1)

    audio_path = sys.argv[1]
    transcribe_audio(audio_path)
```

#### 脚本注意事项

1. **verbose=False**：禁用 Whisper 的详细输出，避免干扰 JSON 解析
2. **fp16=False**：在 CPU 环境下使用 FP32，避免兼容性问题
3. **语言检测**：设置为 None，让模型自动检测语言
4. **规范化路径**：使用 `os.path.normpath()` 处理 Windows 路径分隔符问题
5. **JSON 输出**：使用 `json.dumps()` 格式化输出，移除 `ensure_ascii=False` 以使用默认 UTF-8 编码

**达到什么目的**：

文件位置：`src/main/java/com/anwen/xiamubackend/strategy/impl/LocalModelStrategy.java`

```java
package com.anwen.xiamubackend.strategy.impl;

import com.anwen.xiamubackend.strategy.TranscriptionStrategy;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import java.io.BufferedReader;
import java.io.File;
import java.io.InputStreamReader;

/**
 * 本地模型转录策略
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class LocalModelStrategy implements TranscriptionStrategy {

    @Value("${xiamu.whisper.python-path:python}")
    private String pythonPath;

    @Value("${xiamu.whisper.script-path:scripts/whisper_openai.py}")
    private String scriptPath;

    @Override
    public String transcribe(String audioPath) throws Exception {
        log.info("使用本地模型转写音频: {}", audioPath);

        // 检查脚本是否存在
        File scriptFile = new File(scriptPath);
        if (!scriptFile.exists()) {
            throw new Exception("Whisper 脚本不存在: " + scriptPath);
        }

        // 检查音频文件是否存在
        File audioFile = new File(audioPath);
        if (!audioFile.exists()) {
            throw new Exception("音频文件不存在: " + audioPath);
        }

        // 构建命令
        ProcessBuilder processBuilder = new ProcessBuilder(
            pythonPath,
            scriptPath,
            audioPath
        );

        processBuilder.redirectErrorStream(false);

        log.info("执行 Whisper 脚本: {} {} {}", pythonPath, scriptPath, audioPath);

        Process process = processBuilder.start();

        // 读取标准输出（使用 UTF-8 编码，避免中文乱码）
        StringBuilder output = new StringBuilder();
        try (BufferedReader reader = new BufferedReader(new InputStreamReader(process.getInputStream(), "UTF-8"))) {
            String line;
            while ((line = reader.readLine()) != null) {
                output.append(line).append("\n");
            }
        }

        // 等待进程结束
        int exitCode = process.waitFor();

        if (exitCode != 0) {
            // 读取错误信息
            StringBuilder errorOutput = new StringBuilder();
            try (BufferedReader errorReader = new BufferedReader(new InputStreamReader(process.getErrorStream(), "UTF-8"))) {
                String line;
                while ((line = errorReader.readLine()) != null) {
                    errorOutput.append(line).append("\n");
                }
            }
            throw new Exception("Python 脚本执行失败，退出码: " + exitCode + ", 错误信息: " + errorOutput);
        }

        // 从输出中提取 JSON（找到以 { 开头且以 } 结尾的完整 JSON）
        String fullOutput = output.toString();
        String jsonOutput = extractJson(fullOutput);

        log.info("本地模型转写成功，JSON 长度: {}, 文本长度: {}", jsonOutput.length(), getTextLength(jsonOutput));
        return jsonOutput;
    }

    /**
     * 从输出中提取 JSON 字符串
     * @param output 完整输出
     * @return JSON 字符串
     */
    private String extractJson(String output) {
        // 找到第一个 { 的位置
        int start = output.indexOf("{");
        if (start == -1) {
            return output;
        }

        // 找到最后一个完整的 JSON 对象（以 } 结束且前面有 "text" 字段）
        int end = output.lastIndexOf("}");

        // 从最后往前找对应的 {，确保是完整的 JSON
        while (end > start) {
            // 查找 text 字段的结束引号
            int textEnd = output.lastIndexOf("\"text\": \"", end);
            if (textEnd > start && textEnd < end) {
                // 找到 segments 字段的开始
                int segmentsStart = output.indexOf("\"segments\": [", end);
                if (segmentsStart > start && segmentsStart < end) {
                    // 找到 language 字段的开始
                    int languageStart = output.indexOf("\"language\": \"", end);
                    if (languageStart > start && languageStart < end) {
                        // 找到 language_probability 字段的开始
                        int probStart = output.indexOf("\"language_probability\": ", end);
                        if (probStart > start && probStart < end) {
                            // 找到完整的 JSON 对象
                            end = output.indexOf("}", probStart);
                            if (end > start) {
                                return output.substring(start, end + 1);
                            }
                        }
                    }
                }
            }
            end--; // 往环向前找
        }

        return output.substring(start);
    }

    /**
     * 从 JSON 中提取文本长度
     * @param jsonOutput JSON 字符串
     * @return 文本长度
     */
    private int getTextLength(String jsonOutput) {
        try {
            // 提取 text 字段的值
            int textStart = jsonOutput.indexOf("\"text\": \"");
            if (textStart == -1) {
                return 0;
            }
            int textEnd = jsonOutput.indexOf("\"", textStart + 8); // 跳过 "text": "
            if (textEnd == -1) {
                return 0;
            }
            String textValue = jsonOutput.substring(textStart + 8, textEnd);
            // 移除转义字符
            textValue = textValue.replace("\\n", "").replace("\\\"", "\"").replace("\\\\", "\\");
            return textValue.length();
        } catch (Exception e) {
            log.error("解析文本长度失败", e);
            return 0;
        }
    }
}
```

#### LocalModelStrategy 关键实现说明

1. **UTF-8 编码**：使用 `new InputStreamReader(process.getInputStream(), "UTF-8")` 明确指定编码，避免 Windows 默认 GBK 编码导致的中文乱码

2. **extractJson() 方法**：
   - 从 Python 脚本的完整输出中提取 JSON 部分
   - 通过查找关键字段（text、segments、language、language_probability）定位完整的 JSON 对象
   - 避免将 Whisper 的调试输出误认为是 JSON

3. **getTextLength() 方法**：
   - 从 JSON 中提取 text 字段的值
   - 处理转义字符（\n、\"、\\）
   - 用于日志输出，方便调试

```java
package com.anwen.xiamubackend.service.impl;

import com.anwen.xiamubackend.model.enums.VideoStatusEnum;
import com.anwen.xiamubackend.model.entity.Video;
import com.anwen.xiamubackend.mapper.VideoMapper;
import com.anwen.xiamubackend.service.WhisperTranscriptionService;
import com.anwen.xiamubackend.strategy.TranscriptionStrategy;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;

import java.io.File;

/**
 * Whisper 转录服务实现（使用策略模式）
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class WhisperTranscriptionServiceImpl implements WhisperTranscriptionService {

    private final VideoMapper videoMapper;
    private final ObjectMapper objectMapper = new ObjectMapper();

    private final TranscriptionStrategy localModelStrategy;
    private final TranscriptionStrategy apiCallStrategy;

    @Value("${xiamu.whisper.mode:local}")
    private String mode;

    @Async
    @Override
    public void transcribeAsync(Long videoId, String audioPath) {
        log.info("开始异步转写音频: videoId={}, audioPath={}, mode={}", videoId, audioPath, mode);

        // 1. 查询视频信息
        Video video = videoMapper.selectById(videoId);
        if (video == null) {
            log.error("视频不存在: videoId={}", videoId);
            return;
        }

        // 2. 检查音频路径
        if (audioPath == null || audioPath.isEmpty()) {
            log.error("音频路径为空: videoId={}", videoId);
            updateTranscriptionFailed(video, "音频路径为空");
            return;
        }

        // 3. 检查音频文件是否存在
        File audioFile = new File(audioPath);
        if (!audioFile.exists()) {
            log.error("音频文件不存在: videoId={}, audioPath={}", videoId, audioPath);
            updateTranscriptionFailed(video, "音频文件不存在");
            return;
        }

        // 4. 更新状态为处理中
        updateStatus(video, VideoStatusEnum.PROCESSING.getCode());

        try {
            // 5. 根据模式选择策略
            TranscriptionStrategy strategy = getStrategy();

            // 6. 执行转写
            String result = strategy.transcribe(audioPath);

            // 7. 解析 JSON 结果
            JsonNode jsonNode = objectMapper.readTree(result);

            // 检查是否有错误
            if (jsonNode.has("error")) {
                String error = jsonNode.get("error").asText();
                throw new Exception(error);
            }

            // 8. 获取转写文本
            String transcript = jsonNode.get("text").asText();

            // 9. 获取语言信息（可选，可用于后续处理）
            String language = jsonNode.has("language") ? jsonNode.get("language").asText() : "";

            log.info("转写成功: videoId={}, language={}, textLength={}", videoId, language, transcript.length());

            // 10. 更新数据库
            video.setTranscript(transcript);
            video.setStatus(VideoStatusEnum.WAITING.getCode());  // 转写成功，等待下一步 AI 分析
            videoMapper.updateById(video);

        } catch (Exception e) {
            log.error("转写失败: videoId={}", videoId, e);
            updateTranscriptionFailed(video, "转写失败: " + e.getMessage());
        }
    }

    /**
     * 根据配置获取策略
     * @return 转录策略
     */
    private TranscriptionStrategy getStrategy() {
        switch (mode.toLowerCase()) {
            case "api":
                log.info("使用 API 调用策略");
                return apiCallStrategy;
            case "local":
            default:
                log.info("使用本地模型策略");
                return localModelStrategy;
        }
    }

    /**
     * 更新状态
     */
    private void updateStatus(Video video, String status) {
        video.setStatus(status);
        videoMapper.updateById(video);
    }

    /**
     * 更新转写失败
     */
    private void updateTranscriptionFailed(Video video, String errorMessage) {
        video.setStatus(VideoStatusEnum.FAILED.getCode());
        video.setErrorMessage(errorMessage);
```

### 问题 1：OMP 运行时错误

#### 问题描述

使用 faster-whisper 时，程序在模型加载或转写过程中崩溃，错误信息如下：

```
OMP: Error #15: Initializing libiomp5md.dll, but found libiomp5md.dll already initialized.
```

#### 原因分析

faster-whisper 依赖的多个库（如 PyTorch、onnxruntime 等）都使用了 OpenMP（Open Multi-Processing）并行计算库。在 Windows 环境下，当多个库同时尝试初始化 OMP 运行时时，会产生冲突。

#### 尝试的解决方案

1. **设置环境变量 `KMP_DUPLICATE_LIB_OK=1`**
   ```python
   import os
   os.environ["KMP_DUPLICATE_LIB_OK"] = "TRUE"
   ```
   - 结果：无效，程序仍然崩溃

2. **使用 CPU 模式**
   ```python
   model = WhisperModel('small', device='cpu', compute_type='int8')
   ```
   - 结果：仍然出现 OMP 错误

#### 最终解决方案

**切换到 openai-whisper（官方版本）**

官方的 openai-whisper 库对 Windows 环境的兼容性更好，内部处理了 OMP 运行时冲突问题。

```bash
pip uninstall faster-whisper
pip install openai-whisper
```

对应的 Python 脚本修改为：

```python
import whisper

# 使用官方 openai-whisper
model = whisper.load_model("small")
result = model.transcribe(
    audio_path,
    language=None,
    task="transcribe",
    verbose=False,
    fp16=False
)
```

#### 经验总结

- faster-whisper 虽然性能更好，但在 Windows 环境下存在兼容性问题
- openai-whisper 官方版本更稳定，适合生产环境
- 如果后续需要更高性能，可以考虑在 Linux 环境下使用 faster-whisper

### 问题 2：JSON 解析错误 - "Unrecognized token 'Detected'"

#### 问题描述

Java 端解析 Python 脚本输出时，Jackson 解析器报错：

```
com.fasterxml.jackson.core.JsonParseException: Unrecognized token 'Detected': was expecting (JSON Literal, Number, Array, Object or Token 'null')
```

#### 原因分析

在初始实现中，Python 脚本使用了 `verbose=True`，导致 Whisper 库输出调试信息到标准输出：

```
[00:00:00.000 --> 00:00:03.500]  第一段文本
Detected language: Chinese with probability 0.95
{
  "text": "完整的转写文本",
  ...
}
```

Java 读取了所有标准输出，包括 "Detected language: Chinese" 等调试信息，导致 JSON 解析失败。

#### 解决方案

**方案 1：移除所有调试输出**

在 Python 脚本中：
1. 设置 `verbose=False` 禁用 Whisper 的详细输出
2. 移除所有 `print("[DEBUG] ...")` 调试语句

```python
result = model.transcribe(
    audio_path,
    language=None,
    task="transcribe",
    verbose=False,  # 禁用详细输出
    fp16=False
)

# 只输出 JSON，不输出任何调试信息
print(json.dumps(output, indent=2))
```

**方案 2：在 Java 端过滤输出**

添加 `extractJson()` 方法，从完整输出中提取 JSON 部分：

```java
private String extractJson(String output) {
    int start = output.indexOf("{");
    if (start == -1) {
        return output;
    }
    int end = output.lastIndexOf("}");
    return output.substring(start, end + 1);
}
```

#### 最终方案

结合方案 1 和方案 2：
1. Python 端禁用 verbose，移除所有调试输出
2. Java 端保留 `extractJson()` 方法作为容错机制，确保即使有意外输出也能正确解析

#### 经验总结

- 跨语言调用时，务必明确通信协议（JSON、纯文本等）
- Python 脚本应该只输出结果数据，避免输出调试信息
- 双重校验（源头过滤 + 端点容错）可以提高系统健壮性

### 问题 3：数据库中文乱码

#### 问题描述

Python 脚本单独运行时，输出的 JSON 包含正确的中文字符。但通过 Java 项目调用后，存储到数据库中的中文字符变成乱码：

```
正确输出："完整的转写文本"
数据库存储："??????????"
```

#### 原因分析

Windows 系统默认使用 GBK 编码，而 Java 项目使用 UTF-8 编码。

1. Java 的 `InputStreamReader` 在未指定编码时，使用系统默认编码（Windows 下为 GBK）
2. Python 脚本输出的是 UTF-8 编码的字符
3. 使用 GBK 解析 UTF-8 数据会导致乱码

#### 解决方案

在 Java 端明确指定 UTF-8 编码：

```java
// 修改前
try (BufferedReader reader = new BufferedReader(new InputStreamReader(process.getInputStream()))) {

// 修改后
try (BufferedReader reader = new BufferedReader(new InputStreamReader(process.getInputStream(), "UTF-8"))) {
```

同时在错误输出流也使用 UTF-8：

```java
try (BufferedReader errorReader = new BufferedReader(new InputStreamReader(process.getErrorStream(), "UTF-8"))) {
```

#### 验证方法

1. 在 Java 日志中打印转写结果：
   ```java
   log.info("转写结果: {}", transcript);
   ```

2. 检查数据库中的数据：
   ```sql
   SELECT transcript FROM video WHERE id = ?;
   ```

3. 确认中文字符正确显示

#### 经验总结

- 跨平台项目务必明确指定字符编码
- Windows 默认编码是 GBK，Linux/Mac 默认是 UTF-8
- 始终使用 UTF-8 作为统一的字符编码标准

### 问题 4：文本长度变少（从 4000+ 到 2958）

#### 问题描述

最初的 `extractJson()` 方法过于简单，导致 JSON 被截断，文本长度从 4000+ 字符减少到 2958 字符。

```java
// 简单实现（有问题）
private String extractJson(String output) {
    int start = output.indexOf("{");
    int end = output.lastIndexOf("}");
    return output.substring(start, end + 1);
}
```

#### 原因分析

JSON 中可能包含嵌套结构，简单的 `lastIndexOf("}")` 可能会找到错误的结束位置，导致 JSON 被截断。

#### 解决方案

改进 `extractJson()` 方法，通过验证关键字段的存在来确保找到完整的 JSON：

```java
private String extractJson(String output) {
    // 找到第一个 { 的位置
    int start = output.indexOf("{");
    if (start == -1) {
        return output;
    }

    // 找到最后一个完整的 JSON 对象
    int end = output.lastIndexOf("}");

    // 从最后往前找，确保是完整的 JSON
    while (end > start) {
        // 验证关键字段存在
        int textEnd = output.lastIndexOf("\"text\": \"", end);
        int segmentsStart = output.indexOf("\"segments\": [", end);
        int languageStart = output.indexOf("\"language\": \"", end);
        int probStart = output.indexOf("\"language_probability\": ", end);

        if (textEnd > start && segmentsStart > start &&
            languageStart > start && probStart > start) {
            // 找到完整的 JSON 对象
            end = output.indexOf("}", probStart);
            if (end > start) {
                return output.substring(start, end + 1);
            }
        }
        end--; // 往前找
    }

    return output.substring(start);
}
```

同时添加 `getTextLength()` 方法直接从 JSON 中提取文本长度：

```java
private int getTextLength(String jsonOutput) {
    try {
        int textStart = jsonOutput.indexOf("\"text\": \"");
        if (textStart == -1) {
            return 0;
        }
        int textEnd = jsonOutput.indexOf("\"", textStart + 8);
        if (textEnd == -1) {
            return 0;
        }
        String textValue = jsonOutput.substring(textStart + 8, textEnd);
        // 移除转义字符
        textValue = textValue.replace("\\n", "").replace("\\\"", "\"").replace("\\\\", "\\");
        return textValue.length();
    } catch (Exception e) {
        log.error("解析文本长度失败", e);
        return 0;
    }
}
```

#### 经验总结

- 处理 JSON 时要考虑嵌套结构
- 简单的字符串查找可能不准确
- 验证关键字段的存在可以提高可靠性

### 问题 5：语速快导致的识别不准确

#### 问题描述

当音频中的人说话语速很快或发音不清晰时，Whisper 的识别准确率下降。

#### 优化方案（未实现，供参考）

| 方案 | 说明 | 优缺点 |
|------|------|--------|
| **使用更大的模型** | 从 small 升级到 medium 或 large 模型 | ✅ 准确率提升 ❌ 模型更大，速度更慢 |
| **音频预处理** | 对音频进行降噪、音量增强、语速调整 | ✅ 提升输入质量 ❌ 需要额外的音频处理工具 |
| **调整 beam_size** | 增加 beam search 大小（默认 5） | ✅ 提升准确率 ❌ 处理时间变长 |
| **多次识别取最优** | 对同一段音频识别多次，选择置信度最高的结果 | ✅ 提升准确率 ❌ 处理时间成倍增加 |
| **语言模型后处理** | 使用 LLM（如 GPT）对识别结果进行纠错和润色 | ✅ 纠错能力强 ❌ 需要额外的 API 调用成本 |
| **分段识别** | 将长音频按静音分段，分段识别后再合并 | ✅ 每段更清晰 ❌ 可能在分段处丢失信息 |

#### 推荐方案

根据实际需求选择：

1. **轻量级方案**：调整 `beam_size=8`，提高准确率同时保持较快速度
2. **平衡方案**：使用 medium 模型，在准确率和速度之间取得平衡
3. **高准确率方案**：使用 large 模型 + 音频预处理，适合对准确率要求高的场景
4. **生产级方案**：使用 small 模型快速识别，然后用 LLM 进行后处理纠错

#### 实现示例（调整 beam_size）

- 语速快是语音识别的常见挑战
- 需要在准确率、速度、成本之间权衡
- 可以根据场景组合使用多种优化方案

### 当前处理链路

`上传视频 -> 提取音频 -> Whisper 转写 -> AI 摘要 -> AI 章节 -> 写入 summary/chapters -> SUCCESS`

### 当前限制

- API 调用方式的 Whisper 转写策略仍为预留状态，当前实际可用的是本地模型策略
- 章节生成目前基于单次 LLM 调用和截断后的分段 JSON，超长视频仍存在进一步分段优化空间
- 文件清理当前以物理文件保留期为主，尚未做更细粒度的重试窗口与状态联动
